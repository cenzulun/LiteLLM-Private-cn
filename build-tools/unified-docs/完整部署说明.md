# AI大模型智能网关平台完整 ARM64 部署

本目录为网关与推理调度服务统一交付，所有应用镜像均为 linux/arm64。适用于 openEuler ARM64 容器主机。数据库、缓存、监控和现有模型引擎由内网环境提供，Compose 不启动数据库或推理引擎。

## 导入与启动

完整解压部署包后执行 `sha256sum -c SHA256SUMS`，镜像已在包内，无需访问公网。首次启动前配置已有数据库和缓存。

```sh
python3 init_env.py --database-url 'postgresql://用户名:密码@内网数据库:5432/独立数据库' --redis-host '内网缓存' --redis-port 6379 --redis-username '缓存用户名' --redis-password '缓存密码' --bind-address '内网网卡地址'
chmod +x start.sh
./start.sh
docker compose ps
```

启动脚本会导入 `all-images-arm64.tar`，核对 Compose 使用的每个镜像实际架构，再同时启动网关和调度服务。镜像已导入时可执行 `LOAD_IMAGE=false ./start.sh`。不能将旧 AMD64 镜像改名后使用。

已有 `.env` 不会被覆盖。升级前备份数据库、加密盐值和持久化卷，在原配置中将 GATEWAY_IMAGE 更新为 realai/gateway:1.0.10-arm64，补充 MOTOR_IMAGE=realai/motor:3.2.0-runtime-arm64。保留 LITELLM_SALT_KEY。首次数据库迁移使用独立库和有迁移权限的账号。

首次迁移与启动可能较慢，默认迁移等待和启动等待均为 1800 秒，可在 `.env` 中调整 `LITELLM_PRISMA_MIGRATE_DEPLOY_TIMEOUT`、`LITELLM_MIGRATION_LOCK_TIMEOUT` 和 `START_TIMEOUT_SECONDS`。数据库未完成迁移时，服务会停止启动；不能通过反复重启或跳过迁移解决。应先核对该版本迁移 SQL 与实际数据库变更，再按日志使用官方恢复命令。升级迁移前必须备份外部数据库。

登录入口为 `http://内网地址:4100/ui/login/`，管理员账号密码位于本机 `.env`。Redis 支持访问控制用户名、数据库编号和加密连接，设置 REDIS_SSL=true 时需要受信任的内网证书。监控地址可留空，登录后通过“配置监控源”接入已有 Prometheus。

在“推理监控”或“引擎与昇腾资源”右上角选择“配置源采集”，填写独立实例的完整 `/metrics` 地址和调用密钥。后台采集不依赖打开浏览器，原 Prometheus 入口继续保留。采集配置和加密密钥保存于现有 PostgreSQL，历史文件自动创建在原 `motor_module_state` 卷。详细配置、统计口径、容量限制和升级说明见包内“直接采集监控接入.md”。

## 推理调度模块

左侧“推理调度”可新增连接。统一 Compose 内填推理地址 http://motor:1025、管理地址 http://motor:1026、观测地址 http://motor:1027、部署控制地址 http://motor:1028。模型名必须与实际引擎返回值一致。

首次 Motor 启动自动在持久化卷生成管理密钥和推理密钥，不写入镜像。由管理员在内网终端查看并填入连接页面，不要把结果发送到聊天或公共仓库。

```sh
docker compose exec motor cat /etc/motor/secrets/management-key
docker compose exec motor cat /etc/motor/secrets/inference-key
```

服务启动和模型调度就绪是不同状态。没有登记实际引擎时，Coordinator 管理接口的 ready=false 是预期状态；容器健康仅表示进程和管理接口存活。必须登记符合 Motor 版本要求的实际引擎实例并验证 ready=true，之后才做真实推理验收。现有普通 vLLM 接口可以直接接入网关；Motor 的实例事件与预填充/解码协议需按实际版本核对，不能假定所有 vLLM 服务都兼容 Motor 纳管。

该包部署 Coordinator 与受限策略控制服务，同一 Motor 镜像包含缓存索引程序。缓存亲和需要另外配置分词器、引擎事件及索引服务，不默认启动。Controller、NodeManager、推理引擎、模型权重和昇腾驱动属于现有集群部署范围，未在本 Compose 中部署。

网关在线路由发布不重启网关。Motor 调度算法变更使用上游启动配置，需要重启对应 Coordinator，会影响其正在处理的请求，页面要求明确确认。拓扑重放与引擎重新就绪需单独验收。

## 持久化与备份

网关模型、账号和路由配置保存在外部 PostgreSQL，Redis 用于共享协调。Motor 连接、加密凭据和操作记录保存在 motor_module_state 卷，Coordinator 配置与密钥在 motor_config 卷，日志在 motor_logs 卷。Motor 管理状态目前为本机 SQLite 卷，不支持多个独立网关主机共享该目录。

备份外部数据库、`.env`、三个 Motor 卷及部署文件。升级不得执行 `docker compose down -v`。恢复加密凭据必须保留相同盐值和 Motor 密钥。建议在维护窗口暂停服务后备份卷，恢复后分别验证连接、拓扑与真实推理。

源码包括完整前端、网关补丁和锁定 Motor 源码。Motor 使用源码标签 3.2.0、提交 96846215cf4f05aaf44068e1784f25d64c18e845，上游 wheel 元数据仍为 3.1.0。包内许可证保留原文。源码重建需要已准备的基础镜像与构建依赖，运行离线镜像不需要联网安装依赖。

## 本版修复与升级

服务地址只检查 HTTP/HTTPS 格式和端口，不再按 RFC 私网地址段判断。企业内使用 148 等地址段时可正常配置；该规则统一适用于模型、路由、Prometheus、调度连接及实例地址。实际连通性由部署网络和防火墙决定。

接口类型显示中文说明，接口路径、配置键、协议字段和模型名称保持原值，例如“对话补全 - /chat/completions”。

基础 Compose 和离线包中的 Compose 均默认启用调度服务，网关声明了启动依赖，直接执行 docker compose up -d 也会启动两项服务。调度页面新增连接时预填配套服务地址，但需要填写真实引擎模型名和密钥并登记实例；容器健康与模型就绪是两种状态。

从旧包升级时保留原 `.env`、数据库和三个持久化卷，将 GATEWAY_IMAGE 改为 realai/gateway:1.0.10-arm64，MOTOR_IMAGE 使用 realai/motor:3.2.0-runtime-arm64。运行新包的 start.sh 导入镜像并更新服务，不要执行 down -v。


## 兼容协议适配修复

通用兼容服务统一使用 openai 协议适配器；该字段只表示协议，不改变已填写的服务地址。已保存的 openai_like 配置在显式指定 api_base 时自动兼容，新建和编辑模型自动规范为 openai。上游实际模型名称、调用地址与密钥保持原值。添加对话模型时选择“内网兼容接口”，实际模型名称可填写 openai/deepseek-v4.1-flash，接口类型选择“对话补全 - /chat/completions”。基础地址为实际服务的 /v1 地址，不能在基础地址重复拼接 /chat/completions。

升级请沿用原 Compose 项目名、原 .env 和所有持久化卷，不运行初始化脚本；只将 GATEWAY_IMAGE 更新为 realai/gateway:1.0.10-arm64。Motor 镜像版本不变。单网关容器更新存在短暂服务中断，需在维护窗口进行。

升级时保留现场 config.yaml 与 monitor-queries.json，不用包内空配置覆盖。若旧 Compose 顶层 name 与新版不同，沿用旧 name 或原启动命令的 -p 参数，防止创建另一套卷。解压后的 SHA256SUMS 用于核验原始交付文件；现场合并 .env、项目名或业务配置后，不再以整包校验作为启动前提，可先 docker load -i all-images-arm64.tar，再执行 LOAD_IMAGE=false ./start.sh。

## 智能路由与负载均衡完整页面

本版 1.0.10 新增模型、实例、时间筛选，上游调用量与速率、流量占比、成功率与失败率、令牌吞吐、同模型重试、备用调用成功率、实例运行与排队、排队时延、首令牌时延、调用时延第九十五和九十九百分位、健康与冷却、选择依据、历史趋势、近期路由记录以及活动告警。详情显示实际实例与模型名称、压力匹配和最近失败分类。

登录后在本页“配置监控源”接入现有 Prometheus，采集网关 `/metrics` 和已有推理引擎指标，按 monitoring/README.md 核对唯一实例标签及告警规则。页面查询地址和自定义指标映射保存到现有 PostgreSQL。未接入监控或没有足够采样时显示暂无数据；没有健康探测时显示尚未探测，不生成演示值。累计次数采用所选时间范围，速率和时延采用五分钟滚动窗口。详细统计口径见 monitoring/README.md。

页面监控可以配置开启，完整页面自身已开发进镜像。真正按运行与排队压力选实例仍需将 REALAI_METRIC_ROUTING_ENABLED=true、PROMETHEUS_URL 和压力表达式配置到网关环境，且路由策略为历史时延路由；修改这些启动参数需更新容器。指标不可用或不能唯一匹配实例时回退到历史时延路由。不同模型仅按管理员配置的备用链切换，通用接口协议兼容不代表模型能力可以无条件互换。

上述启动参数针对 Prometheus 压力来源。1.0.13 的直接采集压力来源在页面保存并开启即可，无需重启网关；仍要求使用历史时延路由、为同模型每个副本分别绑定独立采集源。两种来源不叠加，开启直采压力时优先使用直采，缺少有效匹配数据时回退到历史时延。

## 监控工作台与路由画布

首页显示推理趋势与采集实例表；“推理监控”显示请求、吞吐和时延；“引擎与昇腾资源”显示缓存、进程和设备指标。“趋势指标”可勾选全部指标，也可展开“自选指标”选择多个独立曲线。新增采集源仅展开当前源，已有源通过顶部列表切换；底部同一行提供测试、移除、新增和保存操作。

“智能路由与负载均衡”分为“运行观测”和“策略编排”。“模型与部署→自动路由”也可进入同一份路由画布，原模型分类路由保留在单独标签页。画布选择真实均衡策略与重试、超时、冷却参数，连接模型组的失败备用或上下文超限备用。先“校验编排”，再“发布并生效”；修改后须重新校验。可以“回退上一版”，修订冲突时保留本地草稿并提示重新加载。位置、连线和策略一并持久化，发布不重启服务。

画布定义模型组和备用链，同模型副本由选定的全局策略调度，不是任意工作流执行器。实时压力路由须先发布历史时延策略，并将每个副本的独立采集源绑定到真实部署。没有匹配的新鲜采样时使用历史时延；页面不生成演示流量或虚假健康状态。未接入 Prometheus 时，运行观测也能展示本地已记录的完成调用、成功失败、重试、备用和实例占比；长周期全量趋势仍由监控源提供。

从上一版升级时，把新包中的 `all-images-arm64.tar`、`SHA256SUMS` 和 `upgrade_gateway.sh` 复制到原部署目录，保留原 `.env`、`config.yaml`、`monitor-queries.json` 和编排文件。若原启动命令使用 `-p` 或 `-f`，先设置相同的 `COMPOSE_PROJECT_NAME`、`COMPOSE_FILE`，再执行 `sh upgrade_gateway.sh`。脚本只校验镜像文件、导入镜像、备份并更新原环境中的网关镜像标签，不生成新密钥、不初始化数据库、不删除卷；等待网关健康后才报告成功。

升级不需要重新初始化，已有模型可直接继续使用。新增近期路由记录自动建立在原 motor_module_state 卷，使用独立 routing.sqlite3 文件，不改原调度状态文件。近期记录只保存归类失败原因及路由元数据，不保存提示词、回复正文或密钥。升级前历史不会补录，跨主机集中趋势由现有监控源保存。
