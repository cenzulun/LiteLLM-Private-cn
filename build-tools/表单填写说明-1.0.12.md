# 模型与调度连接填写说明

## 添加内网模型

| 字段 | 填写方法 |
| --- | --- |
| 接入方式 | vLLM-Ascend 等标准协议服务优先选“通用协议兼容接口”。不按模型所属厂商决定协议。 |
| 实际模型名称 | 使用引擎 `/v1/models` 返回的 `data[].id`，保留大小写和路径；表单要求适配器前缀时使用 `openai/实际模型名称`。 |
| 对外模型名称 | 自定义供业务调用的名称。同一名称的多个部署可参与路由。 |
| 接口类型 | 普通对话选择“对话补全 - /chat/completions”；向量模型选择“向量嵌入 - /embeddings”。按引擎真实能力选择。 |
| 内网服务地址 | 填写网关容器能够访问的服务地址。标准兼容服务一般为 `http://引擎主机:端口/v1`，不要追加 `/chat/completions`。 |
| 调用密钥 | 使用上游服务实际配置的密钥；无鉴权服务按服务要求填写。 |

“通用协议兼容接口”的底层适配器值为 `openai`，仅表示协议，与模型品牌、部署地点无关，也不会把调用改发到外部地址。`OpenAI` 与 `OpenAI_Compatible` 原来同时映射该适配器，因此合并为一个可选项。已有模型的配置不受选项去重影响。

`hosted_vllm` 为 vLLM 服务接口适配；`vllm` 保留进程内调用兼容入口，不能把远端服务当作进程内引擎配置。`zai` 与 `bigmodel` 是不同 GLM 适配器，显式区分；私有化的标准兼容 GLM 服务也可选通用兼容接口。专用适配器同样必须填写实际内网地址。

## 推理调度连接

以下地址仅适用于本交付包中网关与调度服务位于同一 Compose 网络的情况。外部或 Kubernetes 服务需填写网关可达的真实地址。页面中的地址都由网关访问，不是由浏览器访问。

| 字段 | 配套部署填写值或说明 |
| --- | --- |
| 连接名称 | 自定义名称，例如“模型推理池”。 |
| 引擎模型名称 | 与该池所有引擎的 `/v1/models` 返回的 `data[].id` 完全一致。 |
| 推理地址 | `http://motor:1025`，使用根地址，不加 `/v1`。 |
| 管理地址 | `http://motor:1026`。 |
| 观测地址 | `http://motor:1027`，不加 `/metrics`，不是 Prometheus 地址。 |
| 控制器地址 | 默认留空，配套部署未启用独立控制器。 |
| 部署控制地址 | `http://motor:1028`；外部部署未安装配套控制服务时留空。 |
| 部署模式 | 普通完整推理实例选“聚合推理”；仅实际部署预填充/解码分离时选另一项。 |
| 连接超时 | 初始使用 10 秒，按内网网络状况调整。 |
| 推理密钥 | 调度服务首次启动生成的推理密钥。 |
| 管理密钥 | 调度服务首次启动生成的管理密钥，与推理密钥分开。 |
| 验证 TLS 证书 | 使用 HTTPS 时验证服务证书；使用 HTTP 时该项不产生证书校验。 |

配套部署已启用两种鉴权。管理员在部署机分别执行以下命令，将输出填入对应密码框。不要把密钥发到聊天中；平台登录密码、网关管理密钥和引擎密钥均不能替代它们。

```sh
docker compose exec motor cat /etc/motor/secrets/inference-key
docker compose exec motor cat /etc/motor/secrets/management-key
```

填写后先检查连接、保存，再在“实例纳管”登记该模型的引擎实例。实例地址使用 `主机:端口`，不带 `http://` 或接口路径。先验证就绪，再通过“网关接入与测试”接入模型目录并验证真实推理。

一个连接配置对应一个实际模型推理池，同模型副本可登记在一起。14 台服务器承载不同模型时，应分别管理对应池，不能把不同模型全登记为同一个模型的副本。当前配套 Compose 只启动一套 Coordinator，新增多个连接记录不会自动创建多个独立 Coordinator；需要多个独立池时须部署对应调度服务并分别填写地址。也可将全部模型直接接入网关，使用网关路由管理同模型副本与明确配置的备用链。

普通接口兼容不代表引擎一定支持调度器的实例管理和分离推理协议。生产引擎的版本、鉴权及事件协议需要现场联调。未填写实际引擎并通过推理验收前，只能确认配套服务可运行，不能宣称全部生产模型已接通。

## 旧版本升级

无需重新初始化。备份数据库、原 `.env`、部署配置和三个调度持久化卷，沿用原 Compose 项目名和业务配置，只更新网关镜像为 `realai/gateway:1.0.12-arm64`。调度镜像不变。导入离线镜像后，在原部署目录执行：

```sh
docker load -i /新包目录/all-images-arm64.tar
# 修改原 .env 中 GATEWAY_IMAGE 为 realai/gateway:1.0.12-arm64 后执行：
docker compose up -d --pull never motor gateway
```

单网关容器更新会短暂中断访问，应在维护窗口操作。不要重新生成盐值、不要覆盖业务配置、不要执行 `down -v`。页面已有旧资源时刷新后重新进入表单。
