# 1.0.16 监控与路由工作台

- 推理监控、引擎与昇腾资源、智能路由三个入口分别展示推理指标、资源指标与路由状态，移除重复嵌入的完整采集面板。
- 首页将各模型用量明细表替换为推理趋势和采集实例表，保留网关令牌统计。
- 趋势支持全部指标和自选多指标，各指标独立坐标；批量读取历史，缺失采样不补零。
- 采集源改为单项编辑，新增只展开新源；测试、移除、新增、保存归并到同一操作行，高级采集设置默认收起。
- 增加路由画布：拖动模型组、添加节点、连接失败备用和上下文超限备用，校验、发布及回退。均衡策略、重试、超时和冷却参数实际进入网关执行配置。
- 增加实时压力路由开关及绑定采样状态，沿用无新鲜指标时退回历史时延的逻辑。
- 增加持久化调用记录的实际分流统计，未接外部监控源时也可查看已记录的成功、失败、重试、备用及实例占比。
- 使用蓝色操作主色和浅蓝灰工作区；新鲜且有阈值可判断的正常指标显示绿色，阈值触发显示橙色，缺失或过期保持中性色。

## 画布执行边界

均衡策略在同模型的已登记部署副本之间执行。模型节点连线定义失败和上下文超限备用，不定义任意对话语义分类或工作流。入口按客户端请求中的模型名称匹配模型组。发布不重新创建路由器、不重启服务；新请求同步配置，已开始的流式输出继续执行。画布位置和连接与配置修订一起持久化。

节点上的健康与流量使用真实运行数据。无新鲜探测结果显示未知；无完成调用显示等待，不生成虚假流量。网关近期记录统计受三十天和两万条上限约束；长期统计与全部请求吞吐继续由已有监控源提供。

## 原地升级

继续在原部署目录和原 Compose 项目下升级，保留 `.env`、固定加密盐值、数据库、采集历史卷和调度卷。导入新镜像后只修改 `GATEWAY_IMAGE` 并重建网关容器。不要重新运行初始化，不执行 `down -v`。单实例容器更新会有短暂中断，在线路由策略发布不需要容器重启。

Redis 仅密码认证时用户名留空；使用访问控制账户时填写真实存在且启用的账户。原有数据库和 Redis 地址、端口、密码保持原值。离线包不包含现场凭据。
