# 报告中心与模型监控关联

报告中心位于“运行监控”下，沿用统一紧凑页头。页面顶部为报告名称、开始与结束时间、分析模型和生成操作，下面为持久化报告记录。详情在右侧抽屉内展示完整固定模板 HTML，可下载为独立文件。桌面采用四列配置，窄屏顺序堆叠，列表在容器内滚动。生成由后台队列执行，等待、分析、完成、失败状态可见，离开页面不取消任务。

报告分析调用已登记的对话模型，由管理员选择。固定章节包括运行摘要、网关调用与令牌、路由与故障切换、推理及设备指标、历史监控源、模型分析、建议行动、数据覆盖与限制。模型只返回结构化判断，HTML 由平台固定模板渲染，不执行模型生成的代码。报告不收集提示词和回复正文，不将服务地址或密钥送入分析输入。

默认标准版按第一章“整体情况”、第二章“详细情况”、第三章“分析与建议”组织。整体情况包含请求与令牌总量、每秒及每分钟平均请求、有效实例数、排队情况及设备负载对比。详细情况包含各模型与登记副本的排队峰值、采样均值、完成请求速率、令牌吞吐、时延、缓存占用及实际可得的昇腾利用率。图表包括模型请求量、实例最高排队与核心利用率的对比，以及吞吐和排队趋势；只有实际存在的样本才绘制。不能从缓存占用推断算力利用率，未配置阈值的对比使用蓝色。

生成要求默认展开，可直接填写；生成后在详情中打开“报告对话”，调整标题、重点、篇幅、图表开关和详细章节，并选择分析模型。每次发送生成独立修订版，沿用原报告统计范围与冻结数据，原报告保持可查看。对话与各版本结果持久化。每份报告最多二十个版本，模型输入使用最近四轮上下文，界面保留完整版本链。更换统计时间需新建报告，不能把修订版当作重新采集的实时报告。

图表为服务端生成的静态矢量图，嵌入报告文件，不依赖外部图表网站或脚本；报告可在断网环境查看和打印。

报告生成要求默认展开。“定时任务”可新增、编辑、启用、停用或删除任务，也可立即执行。每个任务独立配置分析模型、报告生成要求、执行周期、时刻与最近若干小时的统计范围，执行时间为北京时间。任务到期后进入报告队列，使用同一套数据汇总、模型分析与固定模板流程，最近生成结果可以从任务直接查看。

任务保存在原报告状态数据库中，多工作进程通过事务串行判定并推进下次执行时间，避免同一轮重复入队。停机恢复后错过的多个周期合并补执行一次，统计截止实际入队时刻；队列或存储达到上限时延后。执行中停用只阻止后续计划，不取消已经入队的报告。删除任务不删除已生成报告。最多一百个任务，报告队列与存储沿用原有上限。

选择范围最多三十天。直接采集使用实际保存的时间范围历史，累计令牌计算观测增量并识别计数重置；样本以外和重启间隙的用量无法还原。窗口分位值不视作整段时间分位数。网关用量、引擎用量及监控源统计不能相加。没有数据时保留缺失说明，不能填为零。报告保存于现有持久化状态卷中的独立数据库，适用当前单主机网关、多工作进程部署；跨主机集中报告服务需独立存储方案。

默认自动关联已登记模型的指标接口：从模型基础地址去掉末尾通用接口及 `/v1` 后附加 `/metrics`，保留企业反向代理前缀。模型密钥只在后台使用并随模型密钥变更同步；前端不接收模型密钥原文。仅允许向相同协议、相同主机转发继承的密钥，独立指标端口可自定义；其他主机需显式填写该采集源的独立密钥。

自动关联不意味着接口必然开放指标；不存在 `/metrics`、网络不通或鉴权不符时显示真实错误。手工绑定相同部署的采集源优先，避免重复采集。可在配置中修改指标地址、停用自动源或关闭新模型自动发现，配置继续持久化。昇腾设备指标仍需实际设备导出器。
